# Every entry is bounded on BOTH sides: a lower bound for the oldest release
# whose API this code actually uses, and an upper bound at the next MAJOR
# version (next minor for the 0.x packages, where a minor bump is the breaking
# one under semver). Lower bounds alone made a fresh `pip install -r` resolve to
# whatever had been released that day, so two installs of the same commit could
# disagree — exactly how a passing suite turns into a red CI run with no code
# change. The upper bounds below were chosen against the versions this suite is
# verified green on (statsmodels 0.14.6, pandas 3.0.6, numpy 2.5.3, scipy
# 1.18.1, scikit-learn 1.9.1, xgboost 3.4.1, arch 8.0.0, torch 2.14.1,
# streamlit 1.65.0, plotly 7.1.0, pytest 9.1.1): the ceilings allow those and
# anything compatible after them, and block the next major on purpose so the
# upgrade is a deliberate, tested commit rather than a surprise.
